## Why Upload Packaging Exists

Docusaurus is configured with:

```ts
url: 'https://allanbpediniv.com',
baseUrl: '/info/',
```

Docusaurus still writes generated files directly into `content-site/build/`, for example `build/index.html` and `build/assets/...`. Cloudflare Pages serves uploaded files relative to the domain root. If `build/` is uploaded directly, `https://allanbpediniv.com/info/` returns 404 because `index.html` is at the upload root instead of under `info/`.

The workflow fixes that by packaging the build output like this:

```text
content-site/cloudflare-pages/
  _headers
  _redirects
  info/
    index.html
    assets/
    img/
    research/
    insights/
    newsroom/
```

The workflow step that does this is `Prepare Cloudflare Pages artifact` in `.github/workflows/deploy.yml`.

## Routing And Headers

`content-site/static/_redirects` contains:

```text
/ /info/ 301
```

During CI this is copied to `content-site/cloudflare-pages/_redirects`, so Cloudflare sees it at the upload root.

`content-site/static/_headers` contains:

```text
/info/assets/*
  Cache-Control: public, max-age=31536000, immutable
```

During CI this is copied to `content-site/cloudflare-pages/_headers`.

## GitHub Actions Setup

The workflow is `Content Site`.

It runs on:

- Pushes to `main` when content-site CI paths change.
- Pushes to `preview` auto-deploy to `https://content-site.lobst3rs.com/info/`.
- Pull requests touching the same paths.
- Manual `workflow_dispatch`; production deploys run from `main` with `target=production`.

Build job:

1. Checks out the repo.
2. Installs Node 20.
3. Runs `npm ci` in `content-site/`.
4. Runs `npm run typecheck`.
5. Runs `npm run build`.
6. Packages `build/` under `cloudflare-pages/info/`.
7. Uploads `cloudflare-pages/` as the deploy artifact.

Deploy job:

1. Downloads the artifact to `content-site/cloudflare-pages/`.
2. Runs `cloudflare/wrangler-action@v3`.
3. Executes:

```bash
pages deploy content-site/cloudflare-pages \
  --project-name=abpiv-personal-brand \
  --branch=<current branch> \
  --commit-hash=<current sha>
```

Production deploys use the GitHub `production` environment and run only by manual `Content Site` workflow dispatch from `main` with `target=production`.

The existing Plausible analytics stack remains separate in `infra/analytics/`. Preview deploys intentionally inject Plausible with `PLAUSIBLE_SITE_DOMAIN=content-site.lobst3rs.com` and same-origin `/_analytics/*` paths, but the current analytics infrastructure only provisions `allanbpediniv.com/_analytics/*`. Preview analytics collection requires extending the separate analytics infrastructure/route first.

## Analytics Behavior

Production builds inject the Plausible script as:

```html
<script>window.plausible=window.plausible||function(){(plausible.q=plausible.q||[]).push(arguments)},plausible.init=plausible.init||function(options){plausible.o=options||{}};plausible.init({endpoint:"/_analytics/api/event"});</script>
<script src="/_analytics/js/script.js" defer data-domain="allanbpediniv.com" data-api="/_analytics/api/event"></script>
```

The `data-api` attribute is required. The Plausible CE script falls back to `new URL(script.src).origin + "/api/event"` when `data-api` is absent. Because this site loads the script from `https://allanbpediniv.com/_analytics/js/script.js`, omitting `data-api` makes browsers POST to `https://allanbpediniv.com/api/event`, which returns `405 Method Not Allowed`.

The public site must keep analytics browser requests same-origin through `https://allanbpediniv.com/_analytics/*`. The dashboard/origin hostname is operator infrastructure only and must not appear in public HTML, JavaScript, or browser network requests.

Expected browser DevTools behavior on production:

- Script request: `https://allanbpediniv.com/_analytics/js/script.js`
- Event request: `https://allanbpediniv.com/_analytics/api/event`
- No analytics requests to non-site domains.

## Base URL Gotcha

Do not hard-code root-relative asset paths like:

```tsx
<img src="/img/headshot.png" />
```

That breaks under `/info/`. Use Docusaurus base URL helpers instead:

```tsx
import useBaseUrl from '@docusaurus/useBaseUrl';

const avatarUrl = useBaseUrl('/img/headshot.png');
```

The homepage hero image was updated this way in `src/components/HomeHero/index.tsx`.
